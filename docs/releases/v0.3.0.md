# Bitaxe Fleet v0.3.0

Ask compatible agents about your fleet using an optional, read-only MCP adapter, and manage access independently for each workspace.

## Highlights

- Enable agent access for a workspace in Settings, then connect an MCP-capable client such as Hermes. Access is off by default, and the adapter runs only when launched by the client.
- Ask for anonymous workspace and miner lists, current status and measurements, fleet summaries, and fleet trends. Miner readings include all-time and session-best share difficulty when available.
- Responses omit names, IP and MAC addresses, pool and worker identities, raw errors, and custom images. They identify demo data, missing readings, freshness, and partial coverage where applicable.
- Agent instructions request permission before direct miner, Fleet API, database, or configuration access. These instructions are advisory and cannot enforce restrictions on other agent tools.
- The workspace settings dialog groups general, monitoring, and agent access options. Visible device IP addresses link to AxeOS in a new tab; screenshot privacy hides the links with the addresses.

## Upgrade notes

- Back up your SQLite database and installation before upgrading. Update the checkout, run `npm ci` and `npm run build`, and restart the API and collector, or rebuild and restart your Compose services without removing the data volume.
- The database is upgraded automatically with a per-workspace agent-access setting. Existing miners, observations, and workspace settings are retained; agent access starts disabled in every workspace.
- Agent configuration is separate and is never changed automatically. See the README's Agent integration section for setup and workspace opt-in. Reload an existing MCP connection after upgrading.
- Client setup examples cover Hermes, OpenClaw, Claude, Codex, Cursor, and VS Code. Hermes connection and tool discovery were checked; the other client recipes have not yet been tested with Fleet.
- The adapter returns stored observations, not new polls. Offline, stale, and unavailable measurements are null. Labels such as `Miner 1` are anonymous and may change when membership changes. Collector health is not reported.
- The adapter filters its own output but does not restrict the existing unauthenticated Fleet API or prevent access through an agent's other tools. Model providers and agent logs may receive returned data. Workspace settings and advisory instructions are not security boundaries.
- Node.js 22.22 or newer is required; Node.js 24 is recommended. The Docker setup uses Node.js 24. Fleet remains a monitoring application; configuration and controls stay in AxeOS.
